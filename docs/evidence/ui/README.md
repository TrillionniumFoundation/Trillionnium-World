# World UI human evidence

This directory stores reviewed, consented evidence packets for the native World
UI. Human evidence is intentionally separate from source tests, screenshots
generated by automation, and local developer assertions.

## Packet contract

Every packet under `sessions/` must conform to
`trnm-world-ui-human-session-v1.schema.json` and pass
`scripts/check-trnm-ui-human-evidence.sh`.

A packet must bind:

- exact commit and Git tree;
- exact release/build/component lock;
- binary SHA-256;
- anonymous participant aliases and roles;
- consent status;
- platform, display and input/accessibility profile;
- session timestamps;
- structured five-second answers;
- vertical-slice completion and facilitator hints;
- artifact hashes and consent scope;
- limitations and reviewer decision.

Do not store names, email addresses, biometric identifiers, private recordings,
or raw personal data in the repository. Store raw media only in the approved
restricted evidence location and reference it by bounded artifact ID and hash.

## Claim-specific pass rules

### UI-HUMAN-001

- at least three independent observers;
- every observer identifies phase, objective and next action correctly;
- at least two observers identify authority and economy posture correctly;
- no observer treats the compatibility lab as Nakama-canonical;
- no observer treats pending CEX work as completed settlement.

### UI-HUMAN-002

- at least one non-developer participant;
- no facilitator gameplay hints;
- the exact NEW -> character -> RPG -> preparation -> RTS -> debrief -> town
  stage set is complete;
- duration is between 600 and 900 seconds.

### UI-HUMAN-003

The reviewed packet set must cover:

- keyboard-only and mouse-only input;
- high contrast;
- subtitles both enabled and disabled;
- low motion;
- 1280x720 and at least one width of 1440 pixels or greater.

## Promotion

`recorded` and `reviewed` packets do not close a gate. `passed` requires an
approved reviewer decision and all claim-specific rules. Any malformed,
automated, unconsented, under-scoped or build-unbound packet fails closed.

These packets cannot enable public online, public player markets,
Nakama-canonical authority, commercial release, or legal approval by
implication.
